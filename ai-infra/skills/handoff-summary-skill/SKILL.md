# handoff-summary-skill — 任务交接总结

## 适用场景

- 任务完成或阶段结束
- 会话切换、模型换班
- 长时间任务中途 checkpoint
- 需要向老板汇报进度
- L3+ 操作完成后需要记录授权与结果
- 发生 failure-analysis 或 security-gate 后需要交接

## 输入要求

```text
任务 ID：
目标：
开始时间：
操作等级：
改动文件：
执行过的命令：
测试结果：
已知风险：
人类确认记录（如有）：
GPT-5.5 复核链接/摘要（如有）：
```

## 输出路径

默认写入：

```text
ai-infra/reports/handoffs/<run-id>/handoff-YYYYMMDD-HHMMSS.md
```

如果配置了 `AI_STATE_DIR`，可同步写入：

```text
${AI_STATE_DIR}/runs/<run-id>/handoff.md
```

`AI_STATE_DIR` 是运行态产物目录，不属于 Skills 定义目录。不得把第三方原始 skills 或 secrets 写入 handoff。

## 输出格式

```markdown
# 任务交接摘要

## 基本信息
- 任务 ID：
- 目标：
- 操作等级：
- 耗时：
- 文件改动数：

## 已完成
- [x] item 1
- [x] item 2

## 未完成
- [ ] item 3（阻塞原因：xxx）

## 文件改动
| 文件 | 改动摘要 | 验证 |
|---|---|---|

## 执行过的命令
| 命令 | 目的 | 结果 |
|---|---|---|

## 安全与授权
- 是否涉及 L3+：
- 是否有人类确认：
- 确认原文：
- GPT-5.5 复核摘要：
- 是否已脱敏：

## 关键决策
1. 为什么选方案 A 而不是 B
2. 什么风险被接受了
3. 什么被明确排除

## 当前状态
- 服务运行：[ ] 是 [ ] 否
- 测试通过：[ ] 是 [ ] 否 [ ] 部分
- 已知问题：[列表]

## 下一步
1. 推荐动作 1
2. 推荐动作 2

## 风险与注意事项
- 风险 1：描述 + 概率 + 影响
- 注意 1：描述
```

## 禁止行为

- 任务没完成写“已完成”
- 隐藏已知问题
- 跳过测试结果报告
- 不记录关键决策原因
- 不记录 L3+ 人类确认
- 把 secrets、token、cookie、SSH key 写入摘要
- 把 GPT-5.5 复核误写成执行授权

## 验证步骤

1. 对照原始目标检查完整性
2. 未完成项都标注阻塞原因
3. 关键决策都有 why
4. 测试结果附在摘要中
5. L3+ 操作附人类确认原文
6. 摘要已脱敏

## 失败停止条件

- 目标未达成且无计划 → 标记为 blocked
- 测试大面积失败 → 生成 failure-analysis
- 关键决策原因不明 → 暂停，回溯决策过程
- 涉及 P0/P1 未关闭 → 不得标记完成
