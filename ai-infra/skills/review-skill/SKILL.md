# review-skill — 外脑 GPT-5.5 复核

## 适用场景

- 架构选型或重大重构
- 安全相关代码：auth、exec、凭据、SSH、端口暴露、浏览器 profile
- 队列/协议/状态机变更
- artifact 下载逻辑变更
- 同一错误签名失败 2 次
- 改动 ≥3 个文件且涉及接口、协议、安全、状态机、队列、artifact
- 改动 ≥5 个文件
- 准备执行 L4/L5 操作
- 需要外发大量上下文给 GPT-5.5

## 与授权的关系

GPT-5.5 复核是风险意见，不是执行授权。L3 及以上操作仍必须由人类操作者或老板给出最新明确确认。agent 不得用 GPT-5.5 结论代替人类确认，不得自行填写 `risk_ack=true`。

## 输入要求

必须包含以下信息，不能只写“帮我看看”：

```text
角色：你是外脑 GPT-5.5 / 复核者
目标：我要实现/修复什么
当前状态：已经做了什么，实际结果是什么
操作等级：L0/L1/L2/L3/L4/L5
关键文件：列出文件名和路径
相关代码：贴脱敏 diff 或关键代码段
错误日志：贴完整脱敏错误输出
安全边界：是否涉及 exec/SSH/凭据/网络/artifact/profile
我怀疑：我的判断（可选）
请你做：审查/找 bug/给替代方案/指出风险
输出格式：结论 + P0/P1/P2/P3 + 验证步骤 + 是否通过
```

## 外发脱敏要求

发给 GPT-5.5 前必须脱敏：

- token / password / cookie / secret / api key
- SSH key / private key
- `.env`
- 浏览器 profile 内容
- localStorage / sessionStorage
- Git/GitHub/Claude 凭据
- 客户数据、个人隐私、生产数据
- 带认证信息的 URL

## GPT-5.5 有效回复标准

有效回复必须同时包含：

1. `【完成】` 完成标记
2. 一句话结论
3. P0/P1/P2/P3 或“没问题”说明
4. 必改项或明确“无必改项”
5. 验证步骤
6. 对 L3+ 操作明确说明“仍需人类确认”

缺任一项视为无效回复，必须继续等待或重新请求。

## 输出格式

复核报告应记录到：

```text
ai-infra/reports/reviews/<YYYYMMDD-HHMMSS>-<task-id>.md
```

报告内容：

```markdown
# GPT-5.5 Review

## 结论
...

## 发现
| 严重度 | 位置 | 问题 | 修复建议 |
|---|---|---|---|

## 必改项
- [ ] ...

## 可选项
- [ ] ...

## 验证步骤
1. ...

## 授权提醒
- GPT-5.5 复核不是执行授权。
- L3+ 仍需人类确认。
```

## 禁止行为

- 不经过 review-skill 直接修改 auth/exec/凭据/队列协议/artifact 下载逻辑
- review 被截断时强行继续
- 只看到 `【完成】` 就当作正确结论
- 拿到结论不执行验证就宣布修复
- agent 自己代替用户确认 L3+ 操作
- 把未脱敏 secrets 发给 GPT-5.5

## 验证步骤

1. 检查 GPT-5.5 回复是否满足有效回复标准
2. 对照 P0/P1/P2/P3 逐项处理
3. P0/P1 必须清零才能继续
4. 执行验证命令或手工验证
5. 将验证结果写入任务报告
6. 若结论与实际结果矛盾，请求二次复核

## 失败停止条件

- GPT-5.5 回复无 `【完成】` → 等完整回复
- GPT-5.5 回复缺少结论、严重度、验证步骤 → 重新请求
- P0/P1 项无法修复 → 生成 failure-analysis，暂停方向
- 同一 review 问题反复 2 次 → 升级为 failure-analysis
